### FR.26 — Link Fidelity, Interactive Links and Output Previews

Complements FR.24 Session Tags (chips under the session header that come from `tag_session`): FR.26 covers links and files inside the transcript text. Source: `docs/refactoring/wpf-programme-plan.md` Appendix A and A13; design `docs/features/focus-references-attachments-previews.md` section 4. New desktop UI for FR.26.2-FR.26.5 is built in WPF only (decision A9); the web client gets the same features through the remote API.

- **FR.26.1 — Full-URL references.** [DONE] Every session's hidden instruction block (FR.11) asks the model to refer to GitHub pull requests, issues and commits, Linear issues and Slack messages by their full URL, for example `https://github.com/tryhardstop/windows-app/pull/196` or `https://linear.app/hardstop/issue/HSE-240`, and never by shorthand such as `PR#196` or `HSE-240`. This applies to worker sessions too.
- **FR.26.2 — Link chips.** The transcript renders recognised URLs (GitHub PR, issue or commit; Linear issue; Slack permalink) as chips with a short label, such as `windows-app#196`, `HSE-240` or the Slack channel name. Any other http(s) URL renders as a plain link. Recognition is pattern-based: no network call and no credentials.
- **FR.26.3 — Preview on click.** Opening a link opens it in the embedded browser pane, and a modifier-click opens the system browser. Until the pane exists, opening a link opens the system browser. In the WPF transcript a link is opened only as FR.26.6 says (Ctrl+left-click); a plain click does not open it.
- **FR.26.4 — Media previews.** [DONE] (WPF and web, 2026-11-15.) When session output contains an https URL whose path ends in an image or video extension, or whose host is on the media allowlist, the transcript offers an inline preview. The allowlist is `catalog.get` `mediaPreviewHosts` (exact host or `*.host` for subdomains only; default `annielartens.online` and `*.githubusercontent.com`; set in the settings file as `MediaPreviewHosts`, no Settings screen yet; decision A13). At most 6 previews per entry, assistant entries only. Nothing is requested before a click, except an image on an allowlisted host.
  - **Web:** an allowlisted host loads automatically (a host without an extension is tried as image, then as video). Every other host shows "Load preview <host>" and nothing is requested before the click. Media elements use `referrerpolicy=no-referrer` and lazy loading. A failure shows "Preview unavailable". Markdown images in entries render as links, never as images (alt text for non-http addresses).
  - **WPF:** the transcript page never requests a remote URL (its policy names only the app's virtual hosts). The host fetches the media. An image on an allowlisted host appears automatically; every other image, and every video, shows "Load preview <host>" and loads only after the click. The host fetches over https only (default port, no credentials, no cookies, no referer, no system proxy), accepts only public addresses (checked again at connect time), checks every redirect hop against the same rules (at most 3), accepts only `image/*` (not svg) and `video/*` content, and caps size (images 10 MB, video 200 MB per file, 1 GB per view) and time. A video plays from a local cache copy. Markdown in entries, Focus items and the preview never creates an element that loads a resource: images show their alt text, link titles are dropped and the HTML goes through an allowlist sanitizer.
  - Not built: a Settings screen for the allowlist; a cancel control and progress for video downloads.
- **FR.26.5 — Local files inline.** [DONE] (WPF and web 2026-11-15 as chips under the message; WPF revised 2026-11-17 to inline paths; the web client keeps its chips until its own change.) An absolute local path (`C:\...`, `c:/...`, `\\server\...`; spaces allowed inside backticks or quotes; a file extension is required) in an assistant entry stays exactly where it is in the text, as text, and is marked as openable: a dotted underline, and the pointer cursor only while Ctrl is held. There is no chip row under the message any more. Opening it (Ctrl+left-click, FR.26.6) asks `file.preview { nodeId, entryId, path }`: the daemon checks that the path occurs in that entry's text, applies the FileAccess policy (FR.23.18, decision A11) and returns a handle for `file.read`. The client then opens the preview (WPF: the preview pane; web: the preview sheet; see FR.23.18). This holds for every kind of file the preview shows (text, `.md`, `.csv`, `.txt`, code, images, ...). A refusal shows a dismissible message, never a dialog. An entry without `entryId` gets no openable paths. **Images** (png, jpg, jpeg, gif, bmp, webp): the path stays inline and, directly under it on the next line, the image preview appears, sized to the column (at most 360 px high) and selectable and copyable like any page content. It is shown for the first occurrence of each image path in the entry. The preview goes through the same checks as opening: the daemon's `file.preview` (path occurs in the entry, FileAccess policy, referenced files, attachments and the session working directory; A11, A13), then the host copies the image into its preview cache and the page shows it from there (the page never reads a local file itself). When the policy refuses the file, the path stays and a small "Image not allowed" hint takes the place of the preview; a missing or unreadable file shows "Image unavailable". Ctrl+left-click on the path or on the image opens the file as above. When an image has loaded the entry is measured again. svg is a text type here (never rendered): its path is openable but gets no inline image.

- **FR.26.6 — Ctrl+click opens, a plain click selects.** [DONE] (WPF, 2026-11-17.) In the WPF transcript a link, a local path (FR.26.5) and an inline image open only on Ctrl+left-click (no Shift or Alt; other buttons do nothing). A plain click on them does nothing, so text and images can be selected and copied: a drag over a path, a link or an image selects them as it does any text. A web link keeps the existing safe-URL policy (http and https only; anything else stays inert) and opens as FR.26.3 says. Links, paths and images show the pointer cursor only while Ctrl is held. Unchanged: "Show full entry" and "Load preview" are plain buttons, Up/Down input navigation, find, reference jumps and the virtualised measuring work as before. Use case UC.LK.01, test cases TC.LK.01.
