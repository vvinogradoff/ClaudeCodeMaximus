### FR.26 — Link Fidelity, Interactive Links and Output Previews

Complements FR.24 Session Tags (chips under the session header that come from `tag_session`): FR.26 covers links and files inside the transcript text. Source: `docs/refactoring/wpf-programme-plan.md` Appendix A and A13; design `docs/features/focus-references-attachments-previews.md` section 4. New desktop UI for FR.26.2-FR.26.5 is built in WPF only (decision A9); the web client gets the same features through the remote API.

- **FR.26.1 — Full-URL references.** [DONE] Every session's hidden instruction block (FR.11) asks the model to refer to GitHub pull requests, issues and commits, Linear issues and Slack messages by their full URL, for example `https://github.com/tryhardstop/windows-app/pull/196` or `https://linear.app/hardstop/issue/HSE-240`, and never by shorthand such as `PR#196` or `HSE-240`. This applies to worker sessions too.
- **FR.26.2 — Link chips.** The transcript renders recognised URLs (GitHub PR, issue or commit; Linear issue; Slack permalink) as chips with a short label, such as `windows-app#196`, `HSE-240` or the Slack channel name. Any other http(s) URL renders as a plain link. Recognition is pattern-based: no network call and no credentials.
- **FR.26.3 — Preview on click.** Opening a link opens it in the embedded browser pane, and a modifier-click opens the system browser. Until the pane exists, opening a link opens the system browser. In the WPF transcript a link is opened only as FR.26.6 says (Ctrl+left-click); a plain click does not open it.
- **FR.26.4 — Media previews.** [DONE] (WPF and web, 2026-11-15.) When session output contains an https URL whose path ends in an image or video extension, or whose host is on the media allowlist, the transcript offers an inline preview. The allowlist is `catalog.get` `mediaPreviewHosts` (exact host or `*.host` for subdomains only; default `annielartens.online` and `*.githubusercontent.com`; set in the settings file as `MediaPreviewHosts`, no Settings screen yet; decision A13). At most 6 previews per entry, assistant entries only. Nothing is requested before a click, except an image on an allowlisted host.
  - **Web:** an allowlisted host loads automatically (a host without an extension is tried as image, then as video). Every other host shows "Load preview <host>" and nothing is requested before the click. Media elements use `referrerpolicy=no-referrer` and lazy loading. A failure shows "Preview unavailable". Markdown images in entries render as links, never as images (alt text for non-http addresses).
  - **WPF:** the transcript page never requests a remote URL (its policy names only the app's virtual hosts). The host fetches the media. An image on an allowlisted host appears automatically; every other image, and every video, shows "Load preview <host>" and loads only after the click. The host fetches over https only (default port, no credentials, no cookies, no referer, no system proxy), accepts only public addresses (checked again at connect time), checks every redirect hop against the same rules (at most 3), accepts only `image/*` (not svg) and `video/*` content, and caps size (images 10 MB, video 200 MB per file, 1 GB per view) and time. A video plays from a local cache copy. Markdown in entries, Focus items and the preview never creates an element that loads a resource: images show their alt text, link titles are dropped and the HTML goes through an allowlist sanitizer.
  - Not built: a Settings screen for the allowlist; a cancel control and progress for video downloads.
- **FR.26.5 — Local files inline.** [DONE] (WPF and web 2026-11-15 as chips under the message; WPF revised 2026-11-17 to inline paths; the web client keeps its chips until its own change.) An absolute local path (`C:\...`, `c:/...`, `\\server\...`; spaces allowed inside backticks or quotes; a file extension is required) in an assistant entry stays exactly where it is in the text, as text, and is marked as openable: a dotted underline, and the pointer cursor only while Ctrl is held. There is no chip row under the message any more. Opening it (Ctrl+left-click, FR.26.6) asks `file.preview { nodeId, entryId, path }`: the daemon checks that the path occurs in that entry's text, applies the FileAccess policy (FR.23.18, decision A11) and returns a handle for `file.read`. The client then opens the preview (WPF: the preview pane; web: the preview sheet; see FR.23.18). This holds for every kind of file the preview shows (text, `.md`, `.csv`, `.txt`, code, images, ...). A refusal shows a dismissible message, never a dialog. An entry without `entryId` gets no openable paths. **Images** (png, jpg, jpeg, gif, bmp, webp): the path stays inline and, directly under it on the next line, the image preview appears, sized to the column (at most 360 px high) and selectable and copyable like any page content. It is shown for the first occurrence of each image path in the entry. The preview goes through the same checks as opening: the daemon's `file.preview` (path occurs in the entry, FileAccess policy, referenced files, attachments and the session working directory; A11, A13), then the host copies the image into its preview cache and the page shows it from there (the page never reads a local file itself). When the policy refuses the file, the path stays and a small "Image not allowed" hint takes the place of the preview; a missing or unreadable file shows "Image unavailable". Ctrl+left-click on the path or on the image opens the file as above. When an image has loaded the entry is measured again. svg is a text type here (never rendered): its path is openable but gets no inline image (decision: no svg preview). **Video** paths get a first-frame preview as FR.26.6 says.

- **FR.26.6 — Ctrl+click opens, a plain click selects.** [DONE] (WPF, 2026-11-17.) In the WPF transcript a link, a local path (FR.26.5) and an inline image open only on Ctrl+left-click (no Shift or Alt; other buttons do nothing). A plain click on them does nothing, so text and images can be selected and copied: a drag over a path, a link or an image selects them as it does any text. A web link keeps the existing safe-URL policy (http and https only; anything else stays inert) and opens as FR.26.3 says. Links, paths and images show the pointer cursor only while Ctrl is held. Unchanged: "Show full entry" and "Load preview" are plain buttons, Up/Down input navigation, find, reference jumps and the virtualised measuring work as before. **Video (FR.26.6, added 2026-11-18).** A path to a video (mp4, mov, webm, mkv, avi, m4v, wmv) shows the **first frame** on the line under the path (first occurrence in the entry, like an image), sized like the image previews (fitted to the column, at most 360 px high, selectable like any page content), with a small play badge in the middle. The frame is made by the host with the Windows Shell thumbnail API (`IShellItemImageFactory`: the codecs installed on the machine, offline, no extra program; only a real thumbnail counts, never the file-type icon), from a copy of the video that the host fetches through the daemon's `file.read` into the preview cache just long enough for that and then deletes; the frame is a PNG in the preview cache, once per session, entry and path, and the page shows it from there only. The access policy is the one of images (A11, A13; `file.preview` first, so the path must occur in that entry and the FileAccess rules apply): a refusal shows "Video not allowed"; a video over 150 MB (not fetched just for a frame), a damaged file, a type without a codec or a shell that takes longer than 20 s shows "Preview unavailable". **Ctrl+left-click on the path or on the frame opens the file in the default media player** (the Windows shell association) instead of the preview pane: the host fetches the video into the preview cache (once per entry and path; the file is opened from there, never from its original place; the limit of the preview pane applies, 500 MB) and starts it through the same allowlisted launcher as "Open in default app" (mkv, avi and wmv were added to the allowlist and to the daemon's type map). A plain click does nothing, so text and the frame can be selected and copied. svg gets no preview. The preview pane (a Focus reference to a video) still plays mp4, mov, webm, m4v and ogv itself; for mkv, avi and wmv it points to "Open in default app". Use case UC.LK.01 (UC.LK.06), test cases TC.LK.01 (TC.LK.18-TC.LK.25).

Status: FR.26.1 implemented (Phase 0). FR.26.4 and FR.26.5 implemented in WPF and web (2026-11-15; WPF merge `dc2493b`, web merge `b59b14f`). FR.26.5 inline paths with image previews and FR.26.6 (Ctrl+click) implemented in WPF (2026-11-17, branch `wpf/inline-paths`). Video first-frame previews and Ctrl+click in the default media player implemented in WPF (2026-11-18, branch `wpf/inline-video`). ## Amendments (2026-11-19, preview improvements)

| Existing | Amended by | Change |
|---|---|---|
| FR.26.5 Local files inline | FR.26.7 | "An absolute local path" also covers a relative path, as FR.26.7 says: marked, opened and previewed the same way. |
| FR.26.6 Ctrl+click opens | FR.26.7 | A relative path opens on Ctrl+left-click like an absolute one. |

- **FR.26.7 — Relative paths.** A **relative path** in an assistant entry is marked and opened like an absolute one (FR.26.5, FR.26.6): dotted underline, Ctrl+left-click opens it (the preview pane, or its group's preview window, FR.29.4), and images and videos get the same inline previews. *What counts:* at least one folder separator (`/` or `\`) and a file extension on the last part (`docs/features/preview-windows.md`, `code\App.xaml.cs`, `./src/a.ts`, `..\x\y.cs`, `.github/workflows/ci.yml`); spaces only inside backticks or quotes (as for absolute paths); the extension has at least one letter, so `1.2.3/x` is not a path. Also a **bare file name with an extension, only inside backticks** (`` `README.md` ``; a lower-case extension of at most six characters that is on a known file-type list: documents, source, config and data files, images, video and pdf, e.g. `md`, `txt`, `json`, `yml`, `cs`, `ts`, `py`, `png`, `pdf`; so `` `obj.method` ``, `` `os.path` `` and `` `item.name` `` are code and not marked). An apostrophe in prose (`It's`, `don't`) is no quote: a `'` or `"` quote counts only when it opens after the start, a space or `(` and closes before the end, a space or punctuation, and the quoted text is itself a path; a backtick pair is unchanged. Relative paths inside code blocks are marked exactly as absolute ones are (TC.LK.01). *Not marked:* anything inside a link or a URL (`https://x/a.md`, `[t](a/b.md)` keep their link behaviour); a path whose first part looks like a web host, i.e. it ends in a common top-level domain (`com`, `org`, `net`, `io`, `app`, `dev`, `ai`, `co`, `gov`, `edu`, `info`, `biz`, `me`, `us`, `uk`, `de`, `fr`, `ru`, `ca`, `au`, `jp`, `nl`, `xyz`; e.g. `example.com/page.html`; a first part `localhost` counts as a host too); a path that starts with `~`; the target of a markdown link `](...)` (it takes no path slot); version-like text (`1.2.3`, `v2.0`); an absolute path (FR.26.5); paths in user entries (as before). *Opening:* the daemon resolves the text, as written, against the session's working directory (`file.preview`; the text must occur in the entry, FR.26.5). A path that leaves the working directory (`..\..\outside.txt`) is refused with the daemon's message, shown like any refusal (dismissible, no dialog); a missing file shows the usual "File not found" refusal, a missing image "Image unavailable". The web client is unchanged (it keeps its chips for absolute paths). Use case UC.LK.01 (UC.LK.07), test cases TC.LK.01 (TC.LK.26 onwards).

|---|---|---|
| FR.23.18 preview pane: "Text, code, svg, html and scripts are shown only as text" | FR.26.8 | `.html`, `.htm` and `text/html` are shown **rendered** (static policy), with a Source toggle. svg, code and scripts stay text. |
| FR.23.18 preview pane: Source toggle "only for markdown" | FR.26.8 | The Source toggle is also offered for html. |
| FR.26.5 "This holds for every kind of file the preview shows" | FR.26.8 | html is now one of the kinds that render; opening, `file.preview` and the access checks are unchanged. |
| FR.29.5, FR.29.14, FR.29.18 file content and the **Source** (a toggle, only for markdown) | FR.26.8 | Source is also shown for an html file: title-bar icon in a file window, the Source button of a docked panel and of the default Preview panel. |
| The preview kind rule (markdown renders, text kinds show as text) | FR.26.8 | html joins markdown as a rendered kind with a Source toggle. |
| FR.23.18 detail: Open in default app only for md, markdown, txt, images, video and pdf | FR.26.8 (A33) | html and htm are added: the preview-cache copy opens in the default browser, where its scripts run; executables and other scripts are still never launched. |

- **FR.26.8 — HTML files are previewed rendered, with a Source toggle.** WPF only; the web client and the daemon do not change (the daemon already serves the file through `file.preview` and `file.read`).
  - **Which files.** `.html`, `.htm`, and a file the daemon serves as `text/html` without one of the known extensions, wherever a file preview shows: the default Preview panel, docked group panels and preview windows (FR.29.5, FR.29.14, FR.29.18), i.e. the preview pane's renderer. **svg stays text** (FR.26.5 decision unchanged); every other "shown only as text" type is unchanged.
  - **Source toggle.** The same **Source** icon and behaviour as markdown (FR.29.14 title-bar icon in file windows, the Source button of docked panels, the preview pane's toggle): the rendered page by default; Source shows the HTML as text (monospace, as the text kind). The choice is per open item, as for markdown today: opening another file starts rendered again (the view model resets Source when an item loads); a refusal or a load in progress offers no toggle.
  - **Look.** The page shows as it styles itself: a page without its own background is on white, as in a browser. It is not recoloured by Tessyn's theme; the surrounding pane keeps the theme. A theme switch does not change the page.
  - **Policy (Static, decision A31):** the page is drawn as authored and **nothing in it runs or loads from outside**: no scripts, no forms, no frames or objects, no remote images, stylesheets or fonts (they show as missing); inline `<style>`, `style` attributes and embedded `data:` images work. The HTML is **isolated** from the preview page itself (mechanism left to the design); the pane keeps its in-private WebView2 and its strict policy for everything else.
  - **Links.** An http(s) link opens as a link in a markdown preview does (FR.29.4 click sources: the matching group's window or panel, otherwise the system browser). A `#anchor` link scrolls within the page. Other links (relative, `file:`, `javascript:`, `mailto:`) do nothing. No navigation ever replaces the preview inside the pane.
  - **Limits and safety.** Same size limit as text and markdown (2 MB; the first 2 MB are shown with the note). Same access checks (`file.preview`, the path must occur in the entry, the FileAccess policy). Resources **next to** the file (relative css, images, scripts) are not loaded, because the daemon releases only the one file. **Open in default app** is offered (decision A33): it opens the preview-cache copy of the page in the default browser, where its scripts run; files next to the original are missing there as well.
  - **Selection and copy** work as in the markdown view. The preview pane has no Ctrl+wheel zoom (unchanged).
  - **Decision A31 (Architect, 2026-11-19): option 1, Static** (the policy above). Not chosen: (2) **Static + https images and stylesheets** (no scripts), which may come later as a setting if CDN-styled pages turn out to be common; (3) **Full**, scripts run in a separate in-private browser without Tessyn's sign-ins. Reason: nothing from a previewed file runs (the preview pane's rule), no second browser is needed, and **Open in default app** is one click away for a page that needs scripts.
  - **Decision A33 (Architect, 2026-11-20):** Open in default app is offered for html and htm (amends the FR.23.18 allow-list); the page then runs in the default browser, outside Tessyn's policy.
  - Use case UC.LK.01 (UC.LK.08), test cases TC.LK.01 (TC.LK.36–TC.LK.54).
